# SHISHAN004 · 时空错位的文件服务

## 情景

公司的轻量级文件上传与静态资源分发服务。前端与客户端通过上传接口保存文件，并立即根据返回的 URL 请求该资源用于展示或下载。

## 现象

业务方反馈：

> **工单 #5021** —— 「刚上传的文件访问总是报 404，但重启服务后又正常了」
>
> 我们通过 `/api/upload` 成功上传了文件，接口明确返回了成功状态和文件访问路径 `/api/files/xxx`。
> 但紧接着请求这个访问路径，服务端却直接返回 404 Not Found。
> 更离奇的是，只要我们重启一下后台服务，刚才 404 的文件又都能正常访问下载了！
>
> —— 业务前端研发 小胡

请在本地启动服务，复现并排查该异常。

## 服务运行教程

```bash
mvn spring-boot:run
```

启动后：

- 服务监听端口为 `18083`，心跳接口是 `GET /hello`。
- 运行日志写在 `logs/app.log`。

自检服务是否就绪：

```bash
curl http://127.0.0.1:18083/hello
# {"status":"ok"}
```

## 你的任务

定位并修复导致上传成功后立即访问提示 404 的**根因**。

业务验收：
1. 文件上传成功后，立即发起访问请求必须能成功获取文件内容，不得返回 404；
2. 不依赖任何外部构建命令、编译触发或服务重启行为；
3. 对于不存在的文件，应正确返回 404 状态与结构化提示。

约束：
- 项目现有的接口路径、请求体字段、响应结构都是既有契约，不要调整。
- **不要靠屏蔽症状来通过验收**。
