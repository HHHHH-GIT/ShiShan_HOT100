# SHISHAN006 · 流式回复不完整问题

## 情景

客服部门使用的内部智能知识助手，后端接入大模型打字机流式输出（Server-Sent Events / SSE），逐步生成业务解答供客服参考，并将问答记录沉淀至会话历史中。

为保证评测纯粹与环境确定性，本交付包内置了本地模型流式样本回放组件，完全离线运行，不依赖外部 API Key 与外部数据库，会话与消息保存在内存中，重启即重置。

## 现象

> **客服支持组早会质检通报 · 智能助手“日常断气”与“假装完成”**
>
> “智能助手回答问题经常说到一半突然断气，有的甚至一片空白，界面上却大摇大摆地显示『回答完成』！
> 更坑的是，遇到这种半截话去刷新页面或者重新点开左侧历史会话，里面存下来的也是那段被腰斩的残缺文字。不仅答非所问，质检抽检还判定我们回答不完整。”
>
> —— 客服组长 赵敏

在终端可使用自带的样本请求复现该异常流式请求：

```bash
# 1. 创建会话（默认关联 R001 样本，可指定 sampleId）
curl -X POST http://127.0.0.1:18085/api/conversations -H "Content-Type: application/json" -d '{"sampleId":"R003"}'

# 2. 发起流式提问，观察 SSE 输出是否过早断流或丢失内容
curl -N http://127.0.0.1:18085/api/chat/send-stream -H "Content-Type: application/json" -d '{"conversation_id":1,"content":"请解释业务办理流程"}'

# 3. 回读历史记录，核对落库内容与流式输出是否一致
curl http://127.0.0.1:18085/api/conversations/1/messages
```

## 怎么运行

在工程目录执行（需 Node.js 22 或更高版本）：

```bash
npm ci
npm start
```

- 服务地址：`http://127.0.0.1:18085`；心跳为 `GET /hello`，正常返回 `{"status":"ok"}`。
- 日志位置：`logs/app.log`，路径相对工程运行目录。
- 前端页面：浏览器打开 `http://127.0.0.1:18085` 可直接在测试页面选择样本并进行交互。
- 样本说明：工程内置 R001–R014 多组不同格式与网络边界的本地回放用例。

## 边界与验收

- 保持既有接口路径、字段、状态码及 SSE 事件结构（`user_message`、`content`、`thinking`、`done`、`error`）不变。
- 完整遵循标准 SSE 协议规范分词与分块：容许 `data:` 后无空格、多行 `data` 合并以及各类换行格式（LF / CR / CRLF），不得静默丢失合法 JSON 片段。
- 流式输出内容必须与历史回读内容逐字一致；只有收到合法完整的完成凭据 `[DONE]` 且未报错时，方可发送 `done` 并落库为 `completed`。
- 异常中断或缺失完成凭据时，必须发送 `error` 事件并将状态标记为 `failed`，同时保留已接收到的有效内容，不得误标为成功，也不得将错误信息当作正文落库。
- 严禁通过硬编码特定样本编号、跳过解析或将所有请求统一置为失败来规避问题。
