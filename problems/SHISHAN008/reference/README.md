# SHISHAN008 · 张冠李戴

## 情景

研发技术招聘与能力评估平台搭建的代码分析工作台（Coding Interview Workbench），供面试间同一台工位终端上的多个窗口或连续面试交替使用。面试官选择登录账号与分析对象，将代码评估任务推入队列，后台逐一生成包含候选人公开资料、代码样本以及风格统计的分析报告，并支持查看摘要（`summary`）与完整正文（`source`）。

为保证测试与评估的确定性，交付包内置了本地离线数据源（包含 Alice、Bob、Carol 等候选人的真实提交记录及 Dana 空提交记录），完全单机离线运行，不依赖外部力扣网络或第三方包。

## 现象

> **技术面试间共享工位排查备忘录 · 候选人代码“张冠李戴”与源码凭空蒸发**
>
> “秋招技术面试间的公共电脑最近连续反馈灵异状况：
> 1. 上一场面试官老李以 Alice 身份排队提交了报告任务；下一场面试官小王切成 Bob 账号执行队列，结果生成的报告居然显示 Bob 看了 Alice 的源码！更诡异的是，后来 Alice 本人重新登录去查自己的任务，却被系统标记为受限模式（restricted），提示『只能查看公开资料』！
> 2. 另外有面试官反馈，在报告历史中先点进『摘要视图』粗览代码行数，紧接着再切换到『完整源码视图』想细看时，代码详情竟然凭空消失全变成了空字符串，可列表里明明仍显示生成完成...
> 3. 还有几次，排队时选好了特定分析条件，队列执行完后，报告内容却被其他窗口后提交的任务给串改了。”
>
> —— 招聘平台与工程效能支持小组

在终端可使用自带的本地接口复现任务串号与数据异常：

```bash
# 1. 在 desk 工位以 alice 登录并提交正文分析任务
curl -X POST http://127.0.0.1:18087/api/session -H "Content-Type: application/json" -d '{"slot":"desk","account":"alice"}'
curl -X POST http://127.0.0.1:18087/api/reports -H "Content-Type: application/json" -d '{"slot":"desk","target":"alice","view":"source"}'

# 2. 切换窗口登录身份为 bob，再触发任务执行
curl -X POST http://127.0.0.1:18087/api/session -H "Content-Type: application/json" -d '{"slot":"desk","account":"bob"}'
curl -X POST http://127.0.0.1:18087/api/jobs/job-1/run

# 3. 查看生成的报告（检查身份是否被篡改或降权）
curl http://127.0.0.1:18087/api/jobs/job-1
```

## 怎么运行

在工程目录执行（需 Python 3.10 或更高版本）：

```bash
python server.py
```

- 服务地址：`http://127.0.0.1:18087`；心跳为 `GET /api/health`，正常返回 `{"status":"ok"}`。
- 日志位置：`logs/app.log`，路径相对工程运行目录。
- 候选人账本：内置 `alice`、`bob`、`carol`（有完整提交记录）与 `dana`（无提交），可调用 `GET /api/catalog` 查看资料。
- 前端页面：服务启动后浏览器打开 `http://127.0.0.1:18087` 可直接在测试页面查看任务队列并交互调试。

## 边界与验收

- 保持现有所有接口路径、请求体字段、响应结构及 HTTP 状态码不变。
- 会话与身份隔离：任务的提交人、目标对象、语言范围与视图模式必须在提交（`POST /api/reports`）时确定并固化，后续的账号切换、退出或其他任务执行均不得改变既有任务的归属身份与报告内容。
- 权限与可见性自洽：
  - 公开资料对所有访问者开放。
  - 本人报告状态为 `ready`，当 `view="source"` 时可查阅完整源码；为 `summary` 时不输出 `code` 字段，但两种视图下的样本数量、题目分布与代码统计必须严格一致。
  - 游客及非本人报告状态为 `restricted`，代码样本必须为空数组且代码统计指标归零。
- 缓存与不可变性：
  - 内存与持久化缓存不得跨租户/命名空间污染，对外返回的报告视图严禁通过引用修改内部缓存。
  - 本人报告完整生成后，再次查询相同参数、切换展示方式或缩小语言范围时必须命中缓存，严禁重复读取上游本地数据源（通过 `GET /api/source-audit` 验收读取次数）。
- 历史回读真实可靠：`GET /api/history` 必须按提交顺序返回不可变的任务快照，既有报告不得因后续新操作发生漂移。
- 严禁通过硬编码固定单一账号数据、全局屏蔽接口或人为增加超时等待来规避问题。
