# SHISHAN002 · 共享钱包的两副面孔

## 情景

公司的「统一钱包中台」同时给两款游戏供币：

- **星轨**：老游戏，运营三年。玩家可以在星轨里充值，也能把游戏货币拿到交易所做买卖结算。
- **深林**：上个月刚接进来的新游戏。深林自己没有充值入口，玩家在星轨充的钱，深林直接就能用。

两款游戏**共用同一个玩家钱包** —— 同一个人，在星轨里看到的余额和在深林里看到的余额，本来就是同一笔钱。

金币中台由两个团队各自迭代：星轨那套是三年前的老代码，深林是上个月接的。

## 现象

接入深林两周后，客服陆续收到两拨投诉。

### 投诉一

> **工单 #4471** —— 「同一个号，两个游戏里的钱对不上」
>
> 我在星轨里还有一千块，切到深林去就显示 1 块。两个游戏明明是同一个账号、同一个钱包。
> 深林那边我什么都没干过，就是看了一下余额。
>
> —— 玩家 夜航星（P001）

### 投诉二

> **工单 #4493** —— 「充了钱，退出重进就没了」
>
> 充值页面弹出「已到账」，我截图留证了，截图上就是加完之后的数额。
> 可是退出页面再进来看，余额还是充值之前那个数。反复下拉刷新也一样。
> 客服让我重装客户端、换手机、换网络，全都没用。我还以为是我的号出了问题。
>
> —— 玩家 夜航星（P001）

两张工单来自不同玩家的反馈，也不是同一时间报的 —— 请**先在本地把它们各自复现出来**，再动手。

## 服务运行教程

```bash
mvn spring-boot:run
```

启动后：

- 服务监听 `18081`，心跳接口是 `GET /hello`。
- 运行日志写在 `logs/app.log`。
- 种子玩家：`P001`（夜航星）、`P002`（白桦），初始余额均为 1000.000 元。
- 星轨的充值有风控规则：**单笔充值金额不得超过该玩家当前余额的 10 倍**。

自检服务是否就绪：

```bash
curl http://127.0.0.1:18081/hello
# {"status":"ok"}
```

## 你的任务

把这两拨投诉都解决掉。业务上要做到：

1. **同一个玩家，星轨和深林显示的必须是同一笔钱。**
2. **充值成功后立刻看，必须看到充值后的数额**（不能靠重启服务才对）。

约束：

- 星轨的**风控规则不能删**（单笔充值不得超过当前余额的 10 倍），它是业务合规要求。
- 项目里现有的接口路径、请求字段、响应结构都是上下游约定好的，不要改。
- **不要靠屏蔽症状来通过验收**（把报错改成成功、把检查删掉之类）。修完之后，冷启动和跑热了都要对。
