# 分级提示

## L1

- 这几个系统故障并不是单一模块引起的，而是分成不同业务场景的独立问题：
  1. 菜品信息更新后，前台用户看到的内容和后台列表出现差异，这属于数据读取与更新路径的问题；
  2. 订单金额计算偶发差一分钱以及优惠券被重复抵扣，属于计算精度与下单核销流程的问题；
  3. 购物车加减菜品在多并发下偶尔无响应或超时，属于并发执行排队的问题；
  4. 报表统计在跨天导出时缺少无销售的日期、或者多线程导出列表偶发元素为 null，属于统计聚合与集合操作的问题。
- 排查时请将管理端菜品维护、用户端点单下单、多线程导出报表作为独立排查切入点，逐一拆解。

## L2

- **菜品修改与查看**：
  - 当后台更新菜品时，数据库写操作和快速读取副本之间的操作顺序是怎样的？
  - 在多线程并发查询同一道新菜品时，双重检查判断里对共享引用的可见性是否有防护？
  - 查询套餐包含的菜品时，返回给上层的对象会不会被后续业务意外修改？
- **下单与金额**：
  - 订单金额计算过程中，浮点类型的类型转换是否会导致分位舍入丢失？
  - 优惠券使用时的库存校验与抵扣是否具备判断防护？
- **购物车与多线程**：
  - 购物车增加与减少时，如果不同操作对多个对象的持有顺序不一致，在交替执行时会发生什么？
  - 报表多线程并发将数据写入非线程安全集合时，数据完整性如何保证？
- **事务与执行**：
  - 同一个类内部 `this.` 相互调用带 `@Transactional` 的方法，事务切面能否正常生效？

## L3

- 搜索代码中的 `BaseContext`，检查在拦截器的 `afterCompletion` 中是否缺少了对 `ThreadLocal` 的清理逻辑，以及 `AutoFillAspect` 是否存在自动拆箱引发的 NPE。
- 搜索 `DishController` 与 `DishCacheHolder`，查看是否由于先删缓存后更新数据库导致读请求重新加载了旧数据，以及双重检查锁定单例中是否缺少 `volatile` 修饰符。
- 搜索 `ShoppingCartServiceImpl`，对比 `add` 与 `sub` 方法中对 `userId` 与 `dishId` 的 `synchronized` 加锁顺序，统一加锁顺序消除死锁风险。
- 检查 `OrderServiceImpl` 中使用 `doubleValue()` 转换 `BigDecimal` 造成的精度损失，以及优惠券数量扣减时使用原子 CAS 更新（例如 `update coupon set count = count - 1 where id = ? and count > 0`）。
- 检查 `DishServiceImpl` 中的 `deleteBatch`，避免在类内通过 `this.deleteDishWithFlavors` 绕过 Spring 事务代理，并确保批量删除 SQL 在参数列表为空时具备动态条件防护。
