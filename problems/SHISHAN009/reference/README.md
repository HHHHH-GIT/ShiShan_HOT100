# SHISHAN009 · 暴风雨中的外卖系统

## 情景

“苍穹外卖”是一套支撑数十万家餐饮门店的全链路配送系统，涵盖商户端（菜品规格编排、套餐组合管理、订单履约调度、多维财务看板、实时消息推送）与消费者移动端（免密授信、购物车汇总、优惠抵扣、超时关单）。

系统已内置轻量级自包含数据存储驱动与离线模拟环境，预置了商户、菜品、套餐、流水与历史订单快照，无需外部中间件即可独立运行。

## 现象

> **台风暴雨夜大促保障与运维早会纪要**
>
> “台风天外卖单量剧增，早班交接时出现多起异常：
> 1. 客服反馈：部分顾客已取消且显示退款的订单，后台仍显示接单并配送；同一张大额优惠券在并发提交时被连续核销，产生了负数实付账单；
> 2. 财务反馈：购物车算费与提交结算总额出现 1 分钱差异，导致支付校验失败；7 天周期营业额报表返回的金额数组只有 5 个数，无法与日期对应；导出订单明细时丢失了部分记录；
> 3. 后厨反馈：后台停售下架的菜品，小程序刷新后偶尔仍能被加购；某顾客定制的套餐规格影响到了其他顾客看到的套餐详情；
> 4. 运维反馈：未携带身份凭证的更新请求出现鉴权上下文混淆；批量移除菜品时关联规格偶发残留；超时自动处理任务在特定时段出现线程停滞...”
>
> —— 苍穹外卖全国总调度室

在终端可通过本地接口进行基础状态检查与调用验证：

```bash
# 1. 检查服务健康就绪状态
curl http://127.0.0.1:18088/hello

# 2. 模拟商品结算提交
curl -X POST http://127.0.0.1:18088/user/order/submit \
  -H "Content-Type: application/json" \
  -H "authentication: mock_token_user_1" \
  -d '{"addressBookId":1,"payMethod":1,"amount":59.70,"remark":"少放辣"}'

# 3. 查看订单状态与确认
curl -X PUT http://127.0.0.1:18088/admin/order/confirm \
  -H "Content-Type: application/json" \
  -H "token: mock_token_admin" \
  -d '{"id":10}'

# 4. 查询营业额统计报表
curl -X GET "http://127.0.0.1:18088/admin/report/turnoverStatistics?begin=2026-09-01&end=2026-09-07" \
  -H "token: mock_token_admin"
```

## 怎么运行

在工程根目录执行（需 JDK 17+ 与 Maven 3.8+）：

```bash
mvn spring-boot:run
```

- 服务端口：`18088`，心跳检查为 `GET /hello`，正常返回 `{"status":"ok"}`。
- 日志文件：`logs/app.log`，相对工程根目录。
- 内置凭证：管理端凭证 `mock_token_admin`（或账号 `admin` / 密码 `123456`）；移动端凭证 `mock_token_user_1`、`mock_token_user_2`。

## 边界与验收

- 保持所有既有接口路径、请求体参数、响应体结构与错误码规范不变。
- 确保线程池复用下全局请求上下文彻底清理，未鉴权请求严禁带入历史用户或管理员身份。
- 保证订单状态单向流转，已取消退款的订单不得被后续操作逆向覆盖；优惠券不可重复核销，实付金额下限为零。
- 金额汇总与结账计费保持精准，消除浮点数精度截断问题。
- 菜单展示与套餐规格需具备严格的数据独立性与隔离性，避免全局共享对象被引用污染。
- 批量清理操作在入参为空时需安全退出，关联子项在级联移除时保持数据完整性。
- 营业额报表必须以实际结账支付时间为统计基准，日期列表与数值列表保持完整对齐。
- 调度任务与长连接广播需具备并发安全性，杜绝执行阻塞与容器并发冲突。
- 严禁通过硬编码返回值、屏蔽异常日志或关闭校验逻辑绕过验收。
