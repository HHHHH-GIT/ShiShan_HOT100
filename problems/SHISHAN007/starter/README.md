# SHISHAN007 · 用量统计不一致问题

## 情景

研发效能与基础架构团队搭建的内部 AI 辅助工具用量监控服务，接收各办公工位设备定期上报的 Token 消耗数据（按工具、模型及输入/输出/缓存分项），汇总生成日、月及累计维度的用量大盘，并支持查看账户剩余额度。

为保证环境确定性，交付包内置了本地模拟上报数据与回放组件，完全离线运行，不依赖外部数据库与真实设备网络，设备快照保存在内存中，重启即重置。

## 现象

> **月末财务对账与运维晨会交接纪要 · 报表数字“量子波动”**
>
> “月末财务拿报表核算各个团队的 AI Token 账单，结果完全对不上账：各个工具和模型的分项明细加起来，跟报表顶部的 Token 总量根本不一致！
> 更诡异的是值班人员在早班交接时发现，明明没有任何新请求，同一天的日用量和月用量前后看了两次居然变了。运维排查还发现，有的设备仅仅点了一下『刷新额度』，当天的用量明细就突然把昨天的旧数据全卷了进来...”
>
> —— 运维值班工程师 老孙

在终端可使用自带的样本请求复现数据合并与对账异常：

```bash
# 1. 上报第一批设备用量快照
curl -X POST http://127.0.0.1:18086/api/ingest -H "Content-Type: application/json" --data-binary @samples/first.json

# 2. 上报第二批增量数据（模拟跨周期或局部工具上报）
curl -X POST http://127.0.0.1:18086/api/ingest -H "Content-Type: application/json" --data-binary @samples/second.json

# 3. 查询当前汇总统计，比对大盘总数与明细分项
curl http://127.0.0.1:18086/api/stats

# 4. 检查单台设备的快照结构
curl http://127.0.0.1:18086/api/devices/desk-a
```

## 怎么运行

在工程目录执行（需 Node.js 22 或更高版本）：

```bash
npm ci
npm start
```

- 服务地址：`http://127.0.0.1:18086`；心跳为 `GET /api/health`，正常返回 `{"status":"ok"}`。
- 日志位置：`logs/app.log`，路径相对工程运行目录。
- 前端页面：服务启动后浏览器打开 `http://127.0.0.1:18086` 可直接在测试页面查看大盘并提交回访数据。

## 边界与验收

- 保持现有上报与查询接口路径、请求体字段、响应结构及状态码不变。
- 业务日与业务月必须严格以 `Asia/Shanghai` 时区作为自然日/自然月划分基准，不受服务器本地时区与 UTC 零点漂移影响。
- 数据上报时，已采集的工具以本次完整快照为准，未采集的工具在同周期内须完整保留其用量总量及输入/输出/缓存各分项明细，累计窗口始终保留历史。
- 各视角数据必须自洽：窗口总量、工具明细合计数、模型明细合计数以及四项 Token 分项（input / output / cacheRead / cacheWrite）求和必须严格相等。
- 额度刷新（`limitsOnly: true`）仅更新剩余额度，严禁篡改实际用量数值及其所属的用量采集业务时间窗口。
- 严禁通过硬编码固化特定结果、忽略上报请求或屏蔽错误日志来规避问题。
