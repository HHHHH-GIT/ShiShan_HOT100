# SHISHAN007 题解：快照保留的不只是一个总数

## 来源与范围

本题改编自 Javis603/token-monitor v0.15.0 的 `src/shared/usage.js`。工程中还保留了原项目独立的额度窗口与历史报表归一化模块；它们服务于原桌面产品的其他页面，没有接入当前报表链路。排查时需要先区分这些上下文代码和实际请求路径。在原工程中，直接调用设备合并函数就能复现以下行为：

- 未采集工具的 Token 总量得到保留，但缓存读取等分项没有被一起补回。
- 一次 `limitsOnly` 更新保留了用量，却推进了共用的更新时间；后续用量合并据此判断旧数据属于哪个周期。
- 采集端按本地日历统计，合并端的 `utcDayKey` / `utcMonthKey` 按 UTC 判断周期。

原工程相关的 30 个现有用量测试通过，但未覆盖上述组合。本题没有加入价格计算、乱序覆盖、真实账号采集等问题。

题目将复杂的上游采集简化为完整的工具×模型分项，保留日/月/累计快照、部分采集及额度刷新语义。原始分项在 starter 和 reference 都存在；参考答案没有额外私有数据。上游原有费用与会话功能不在本题接口中。版权与 MIT 许可保留在工程的 LICENSE 中。

## 缺陷一：保留总量不等于保留报表

starter 的 `preserveClient` 保留工具总量、模型总量和原始工具/模型分项，却没有补回窗口总览、工具及模型的输入/输出/缓存分项。因此 R001 第二次上报后，合计仍是 175，但保留的 alpha 工具在分项视图中缺少其 100 个 token 的组成。

`REPORT_COMPONENT_DRIFT` 是原始分项与统计投影不一致时派生的日志，不是人为写死的错误标记。删掉日志只会隐藏线索，接口中的数值仍然错误。

修复时，必须从该工具自己的模型分项补回所有统计视角。reference 复用 `addClient`，使总量、工具分项、模型分项与原始矩阵一起更新。

不能把旧的整个模型统计直接加回：两个工具可能使用同一个模型，那样会把本次已经重新采集的工具也重复计算。`shared-model` 测试专门验证此情况。也不能一律保留旧值：本次明确采集到零的工具，旧数据必须被替换。

## 缺陷二：时间戳不是业务日期

`updatedAt` 是一个带时区的时间点，业务窗口则由 Asia/Shanghai 日历决定。UTC 日期字符串不是业务日期键。

例如 `2026-09-28T15:59:00Z` 与 `2026-09-28T16:01:00Z`，UTC 看起来还是同一天，北京时间却已经跨日。相反，`23:59Z` 到次日 `00:01Z` 只是北京时间同一天的 07:59 到 08:01。

reference 使用显式 `timeZone: 'Asia/Shanghai'` 的 `Intl.DateTimeFormat.formatToParts` 生成日/月键，不依赖服务器操作系统的时区。同一套函数也用于设备快照归属与汇总窗口筛选，避免接口之间口径不同。日、月、年边界分别覆盖，累计窗口使用固定键 `all`。

不应把所有窗口都改成“永远保留”或“遇到新请求就清空”；工具未采集时，同周期保留、跨周期丢弃日/月旧值、累计保留历史，三者必须同时成立。

## 缺陷三：额度刷新让旧用量显得更新了

这是最容易被单步排查漏掉的地方。`limitsOnly` 分支直接看没有改动用量，设备查询也仍显示原快照；问题出现在下一次合并。

starter 的周期保留判断读取 `existing.updatedAt`。这个时间同时被额度更新推进了。于是跨周期后先刷新额度，再上报只采集部分工具的新用量时，旧快照可能被误认成属于新周期。

两版都保留 `usageUpdatedAt` 作为用量采集时间，并在额度更新时保持不变。reference 的区别是周期判断使用这个字段；`updatedAt` 仍记录最近一次业务更新，`receivedAt` 仍记录本机收到请求的时间。

R003 的实际过程：原用量为 150；两次额度刷新后用量仍为 150、剩余额度变成 65；隔日 beta 的新用量上报后，日用量为 75，月用量为 525，累计为 1225。昨天 alpha 的 100 不属于新一天，但其当月的 300 与累计的 700 应保留。

只修复时区不够，只在查询时改日期标签也不够。这个问题影响的是后续写入合并结果。测试对照直接采集与插入额度更新后的采集，并验证额度本身确实更新，不能通过忽略额度请求通过。

## 实现差异与公开契约

starter/reference 的源码差异只有 `src/calendar.js` 与 `src/usage.js`。共同模块负责请求校验、原始矩阵归一化、查询、页面和日志；它们不会在读取时偷偷修复 starter 中已经错误保存的统计投影。

服务保留每台设备的最新快照，不是历史数据库。`GET /api/stats` 默认以最新的用量采集时间选择窗口；可用 `at` 选择其他窗口，但不能获取已被替换的历史快照。额度更新不会推进这个默认查询基准。跨设备汇总按各设备快照所属日/月筛选，累计窗口包含全部设备。
