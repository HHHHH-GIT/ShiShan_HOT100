# SHISHAN003 · 失真的文件仓库

## 情景

公司的轻量级附件存储与媒体分发中台。主要为用户提供文档备份与用户头像等资源托管服务，支持附件上传、按哈希索引查询元信息以及下载。

## 现象

客服近期收到两类典型用户投诉：

### 投诉一

> **工单 #3011** —— 「上传成功但仓库里查不到文件」
>
> 我通过系统接口上传了一批业务文档，接口返回了上传成功以及文件哈希。
> 随后我根据接口返回的哈希去查询文件信息并准备下载，服务端却一直提示文件不存在（404）。
>
> —— 业务方 研发李工

### 投诉二

> **工单 #3024** —— 「下载的图片全部损坏打不开」
>
> 之前上传的用户头像与示意图，在通过下载接口取回到本地后，图片查看器提示「文件损坏，无法显示图像」，所有下载下来的图片都无法正常浏览。
>
> —— 运营 小张

请在本地启动服务，分别复现并排查这两个问题。

## 服务运行教程

```bash
mvn spring-boot:run
```

启动后：

- 服务监听端口为 `18082`，心跳接口是 `GET /hello`。
- 运行日志写在 `logs/app.log`。
- 上传的文件默认保存在工作区 `storage/` 目录下。

自检服务是否就绪：

```bash
curl http://127.0.0.1:18082/hello
# {"status":"ok"}
```

## 你的任务

定位并修复导致文件找不到以及下载文件损坏的**根因**。

业务验收：
1. 上传文件后，通过返回的 SHA-256 哈希能够准确命中并获取元数据；
2. 下载图片文件后，二进制内容完整无损，能够被图像工具正常解析打开；
3. 对于包含特定编码符号的文件，内容不发生截断与损坏。

约束：
- 项目现有的接口路径、请求体字段、响应结构都是既有契约，不要调整。
- **不要靠屏蔽症状来通过验收**。
