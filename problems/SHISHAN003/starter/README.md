# SHISHAN003 · 失真的文件仓库

## 情景

一个为业务文档、头像和示意图提供托管的附件服务。调用方上传附件后，保存返回的指纹，用它查询附件信息及下载内容。线上仍有历史客户端接入。

## 现象

> **工单 #3011 · 上传成功后查不到附件**
>
> 上传接口返回成功，也拿到了附件指纹。紧接着用返回的指纹查附件信息，接口却返回 404。
>
> —— 业务研发 李工

> **工单 #3024 · 下载的图片打不开**
>
> 下载头像和示意图后，本地查看器提示“文件损坏”。同一批业务资料里也有能正常读取的文档。
>
> —— 运营 小张

> **工单 #3036 · 部分附件上传失败**
>
> 旧客户端上传某些附件时返回失败。已保留一次请求，文件名和内容由客户端直接提交，没有手工修改。
>
> —— 接入支持 小陈

客户端留存请求可用于本地复现：

```bash
curl http://127.0.0.1:18082/api/files/upload -H "Content-Type: application/json" --data-binary @samples/upload-request.json
```

## 怎么运行

在工程目录执行：

```bash
mvn spring-boot:run
```

- 服务地址：`http://127.0.0.1:18082`；心跳为 `GET /hello`，正常返回 `{"status":"ok"}`。
- 日志位置：`logs/app.log`，路径相对工程运行目录。
- 附件数据目录默认为工程运行目录下的 `storage/`。

## 边界与验收

- 保持现有接口路径、字段及响应结构，兼容留存的历史客户端请求。
- 上传成功后，返回的指纹应能用于查询及下载；指纹采用原始附件字节的 SHA-256，以 64 位小写十六进制表示。
- 下载内容应与上传前的原始附件逐字节一致，不能只保证文件名或可见文本相同。
- 不存在的附件继续返回 HTTP 404；不能将失败响应伪装成上传或下载成功。
