# SHISHAN001 · 请求缓慢问题

一个已经上线的商品库存与订单服务。平时跑得好好的，一到活动时段就不对劲。

## 现象

> **工单 #1024** —— 「一到活动就下单失败」
>
> 平时下单都是好的。晚上八点活动一开，大量下单失败，页面弹「系统繁忙，请稍后重试」。
> 单个人在非高峰期测试又都很正常，难以稳定复现。
>
> —— 运营 王姐

失败时接口返回超时降级：

```json
HTTP 504
{"code":601,"msg":"系统繁忙，请稍后重试","data":null}
```

## 服务运行教程

```bash
mvn spring-boot:run
```

启动后：

- 服务监听 `18080`，心跳接口是 `GET /hello`。
- 运行日志写在 `logs/app.log`。
- 内置商品：`P001`（机械键盘）、`P002`（人体工学椅），初始库存均为 1000000。

自检服务是否就绪：

```bash
curl http://127.0.0.1:18080/hello
# {"status":"ok"}
```

## 你的任务

定位并修复这个问题的**根因**。

业务验收：在高峰并发场景下，相关业务链路保持稳定可用，**不允许再出现任何一次 601 降级错误**。

约束：

- 项目里现有的接口路径、请求字段、响应结构都是上下游约定好的，不要改。
- 超时降级响应（`504` + `code=601`）是既有契约的一部分，不要调整它的形态。
- **不要靠屏蔽症状来通过验收**（把报错改成成功、把检查删掉之类）。修完之后，单请求和并发场景都要是好的。
