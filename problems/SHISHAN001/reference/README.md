# SHISHAN001 · 请求缓慢问题

## 情景

一个已上线的商品库存与订单服务，支持下单、取消和订单查询。活动期间，用户会反复提交和取消订单。

## 现象

> **工单 #1024 · 活动期间订单操作经常失败**
>
> 晚上八点开始活动，顾客点完下单很久没有结果，有人返回“系统繁忙，请稍后重试”。取消订单也遇到了相同提示。活动结束后，我们自己试了几笔又能成功。
>
> —— 运营 王姐

客户端留存的一次响应：

```text
HTTP 504
{"code":601,"msg":"系统繁忙，请稍后重试","data":null}
```

## 怎么运行

在工程目录执行：

```bash
mvn spring-boot:run
```

- 服务地址：`http://127.0.0.1:18080`；心跳为 `GET /hello`，正常返回 `{"status":"ok"}`。
- 日志位置：`logs/app.log`，路径相对工程运行目录。
- 内置商品：`P001`（机械键盘）、`P002`（人体工学椅），初始库存均为 1000000。

## 边界与验收

- 保持既有接口路径、请求字段、响应结构及错误语义。
- 成功下单应生成可查询的订单并扣减库存；取消应恢复相应库存，重复取消不能多恢复。
- 高峰期的合法下单和取消操作应正常完成，已有错误不能被改写为成功响应。
- 服务繁忙时的既有响应格式仍为 HTTP 504 与业务码 601。
