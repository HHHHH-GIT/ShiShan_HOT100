# SHISHAN005 · 消息接收重复问题

## 线上工单背景

我们正在开发一套用于企业内部协同的即时通讯（IM）后台服务。
近期在测试与灰度运行期间，多位业务方用户与前端测试工程师反馈了以下异常现象：

1. **单条消息重复显示**：在移动端弱网或快速点击发送按钮时，聊天对话框中偶发出现两条一模一样的消息，但客户端生成的流水号实际上是一致的。
2. **翻页拉取历史重叠**：向上滚动翻页拉取更早的历史聊天记录时，分页交界处的某一条消息会重复显示两次。
3. **收件箱幽灵推送**：部分消息在发送成功几毫秒后，收件箱中突然多出一条完全相同的内容。
4. **断线重连时间线数量翻倍**：模拟网络断开重连后，全量刷新会话时间线，发现所有消息数量变成了原本的两倍。

前端排查确认：前端组件仅为数据呈现容器，所有列表数据均忠实按后端接口返回渲染。所有的重复数据均来自于服务端的响应。

## 启动与运行

服务使用 Spring Boot 3 构建，运行在端口 `18084`。

编译并启动本地服务：

```bash
mvn spring-boot:run
```

探活检查：

```bash
curl http://127.0.0.1:18084/hello
```

返回 `{"status":"ok"}` 即代表服务已就绪。

## 修复目标与验收标准

1. 保持服务端口 `18084` 及既有 API 契约不变；
2. 彻底消除消息生命周期各阶段（发送、分发、补偿、分页、重连合流）的重复现象；
3. 在本地评测控制台中点击「开始判题」，所有自动化回归测试点全部通过（AC）。
