# SHISHAN005 · 消息接收重复问题

## 情景

公司内部的即时通讯（IM）系统。同事们每天用它聊业务、建群拉通项目，前端网页端和手机 App 都在用。

最近团队重构了消息同步链路，刚灰度上线没两天，各业务群里就炸锅了 —— 大量同事反馈聊天界面里总能看到重复的消息，体验极差。前端同学被产品经理通报批评，熬夜抓包排查后自证清白：接口返回几条前端就渲染几条，前端完全按契约展示，重复数据全部来自后端。

## 现象

> **工单 #7021** —— 「聊天消息频繁异常重复，像自带回声」
>
> 灰度上线后，多个群里频繁出现消息重复展示：
> 有时发一条消息，屏幕上直接冒出来两条一模一样的气泡；
> 有时在群里往上翻看之前的历史记录，翻着翻着某句话又冒出来一次；
> 甚至手机放一会儿再打开或者重连，整屏聊天记录都会莫名其妙全变双份。
> 我们在低峰期单独发几条测试消息看着都挺正常，但只要放到真实交互场景里，各种重复现象就层出不穷。
>
> —— 前端研发 志强

请在本地启动服务，全面梳理消息生命周期与状态流转，定位并解决服务端数据重复问题。

## 服务运行教程

```bash
mvn spring-boot:run
```

启动后：

- 服务监听端口为 `18084`，心跳接口是 `GET /hello`。
- 运行日志写在 `logs/app.log`。

自检服务是否就绪：

```bash
curl http://127.0.0.1:18084/hello
# {"status":"ok"}
```

## 你的任务

定位并修复导致消息异常重复的**根因**。

业务验收：
彻底消除消息在全生命周期各阶段的异常重复，服务端返回的消息流必须全局唯一且数据一致。

约束：
- 项目现有的接口路径、请求体字段、响应结构都是既有契约，不要调整。
- 核心业务接口受 Token 鉴权保护（`Authorization: Bearer <token>`），修改代码时注意保持既有认证及安全拦截完好。
- **不要靠屏蔽症状来通过验收**。修完之后，单请求、状态同步和高频并发都要正常。
