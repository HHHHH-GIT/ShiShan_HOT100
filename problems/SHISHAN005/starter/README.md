# SHISHAN005 · 消息接收重复问题

## 情景

公司内部的即时通讯（IM）系统。同事们每天用它聊业务、建群拉通项目，前端网页端和手机 App 都在用。

最近客户端同学被各路同事骂惨了 —— 聊天界面经常莫名其妙冒出重复的消息。前端同学连夜抓包自证清白：接口返回两条就画两条、返回十条就画十条，前端纯冤枉，锅全在后端服务上。

## 现象

客服和内部反馈群里转交了这几张工单：

### 工单一

> **工单 #7021** —— 「发消息像自带回声」
>
> 在地库信号不好的时候发消息，手机上稍微转了下圈，我就习惯性又点了一下发送。
> 结果界面上硬生生弹出了两条一模一样的消息，别人看也是两条！
> 我用同一个客户端发出去的，流水号明明都是同一条。
>
> —— 销售 小林

### 工单二

> **工单 #7035** —— 「向上翻看聊天记录鬼打墙」
>
> 查以前的项目对接记录，打开聊天框一直往上翻。第一页翻到底再往上拉第二页，
> 刚才上面那句话，在第二页最顶头又冒出来了一遍，每往上翻一页就重现一次。
>
> —— 运营 晓峰

### 工单三

> **工单 #7048** —— 「手机待机回来一看，满屏消息全翻倍」
>
> 手机黑屏待机一会儿再打开，或者在电梯断网出来，App 重新连上拉取聊天记录。
> 页面一刷，之前的聊天记录全部变成双份的了！本来只有 5 句话，直接变成 10 句话。
> 杀掉 App 重新进又变成 5 句。
>
> —— 移动端组长 老徐

请在本地启动服务，把这几类奇怪的重复现象复现出来并排查。

## 服务运行教程

```bash
mvn spring-boot:run
```

启动后：

- 服务监听端口为 `18084`，心跳接口是 `GET /hello`。
- 运行日志写在 `logs/app.log`。

自检服务是否就绪：

```bash
curl http://127.0.0.1:18084/hello
# {"status":"ok"}
```

## 你的任务

定位并修复导致消息异常重复的**根因**。

业务验收：
不管用户是连续重发、翻看历史聊天记录、还是断线重连，聊天消息在收发与展示中都必须是唯一且正常的，**不得再出现任何形式的幽灵重复**。

约束：
- 项目现有的接口路径、请求体字段、响应结构都是既有契约，不要调整。
- **不要靠屏蔽症状来通过验收**。修完之后，单请求、状态同步和高频并发都要正常。
